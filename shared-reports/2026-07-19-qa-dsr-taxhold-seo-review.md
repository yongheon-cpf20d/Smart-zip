## 발견 사항

### 1. [심각도: 중] /dsr — "최대 대출 가능액을 바로 확인할 수 있습니다" 문구가 실제 기능과 다름
- 위치: `app/dsr/page.tsx` 277~278행
- 실제 계산기 동작: 사용자가 `대출원금(newAmount)`을 직접 입력해야 하고, 계산 결과는 그 금액 기준 **DSR 비율(%)**과 "은행권/비은행권 통과 여부"만 보여줌 (224~225행 `bankPass`/`nonBankPass` 로직 참고). 특정 소득에서 빌릴 수 있는 "최대 대출 가능액"을 역산해주는 기능은 코드 어디에도 없음.
- 문제: 사용자가 문구만 보고 "소득 입력하면 최대 대출액이 나오겠구나"라고 기대했다가, 실제로는 대출금액을 직접 넣고 시행착오로 맞춰봐야 함 → 기능 오해 소지.

### 2. [심각도: 중] /tax-hold — SEO 문단과 바로 위 부제목이 같은 페이지에서 서로 다른 세목을 안내
- 위치: `app/tax-hold/page.tsx` 310행(부제목) vs 311~314행(신규 SEO 문단)
- 부제목: "재산세 + 지방교육세 + 도시지역분 + 종합부동산세 + 농어촌특별세" (5개 세목, 실제 계산 결과 화면과 일치 — 497~540행 결과 항목과 대조 확인)
- 신규 문단: "부동산 보유세(재산세+종합부동산세)" (2개 세목만 언급)
- 문제: 바로 위/아래 문장이 세목 구성을 다르게 설명해 대표님/사용자가 봤을 때 정보가 축소·모순되어 보임. 계산 자체는 5개 세목 모두 반영하므로 계산 오류는 아니지만, 문구 정합성 문제.

### 3. [심각도: 낮음] 커밋 메시지의 "GSC 30일 데이터 기준" 표기가 근거 리포트와 불일치
- 근거: `shared-reports/2026-07-19-seo-report.md` 4행 — 분석 기간은 "2026-07-12 ~ 2026-07-18 (최근 7일)"이며, 리포트 본문(27, 38, 42행)에서 "표본이 매우 작음", "30일 기준 재조회"를 **최우선(상) 과제**로 명시하고 있음. `shared-reports/` 폴더에 30일 기준 리포트는 존재하지 않음(파일 1개만 확인됨).
- 문제: 커밋 메시지가 실제로는 7일치 소표본 데이터를 "30일 데이터 기준"이라고 잘못 표기. 리포트가 "상" 우선순위로 지정한 30일 재조회·색인 상태 확인을 건너뛰고 "중" 우선순위 항목(본문 키워드 보강)만 먼저 실행한 순서 문제이기도 함. 페이지에는 노출되지 않는 내부 기록상의 문제이나, 향후 유사 작업 시 근거 데이터 기간을 정확히 표기할 필요.

## 근거
- 1, 2번은 코드(계산 함수·화면 렌더링 로직)와 신규 문구를 직접 대조해 확인한 사실관계 불일치이며, 세법 해석이 개입되지 않아 QA가 직접 판단 가능한 범위임.
- 3번은 리포트 원문 날짜/기간 텍스트와 커밋 메시지를 직접 대조한 결과.

## 권장 조치
- 코딩팀: 
  1. `/dsr` 문구에서 "최대 대출 가능액을 바로 확인" 표현을 "입력한 대출조건 기준 DSR 한도 통과 여부를 확인" 등 실제 기능에 맞게 수정.
